# 0.7.9 動画版Tailscale外部URLの分離

## 背景

同一Windows PC上で音楽版と動画版をTailscale Serveすると、従来の動画版もHTTPS 443の `/` を使用していたため、次のURLが競合した。

```text
https://<PC名>.<tailnet>.ts.net/
```

実機ではこのURLをスマートフォンから開くと音楽版が表示され、動画版へ到達できなかった。

## 方針

音楽版の既存URLを維持したまま、動画版だけTailscale ServeのHTTPS待受ポートを分離する。

```text
音楽版: https://<PC名>.<tailnet>.ts.net/
動画版: https://<PC名>.<tailnet>.ts.net:8443/
```

動画版のローカルHTTPサーバーは従来どおり `127.0.0.1:8876` を使用する。

## Tailscale Serve

動画版の有効化は次と同等のコマンドを使用する。

```text
tailscale serve --yes --bg --https=8443 8876
```

これによりHTTPS 8443だけを動画版の `127.0.0.1:8876` へリバースプロキシする。HTTPS 443で稼働する音楽版のServe設定は変更しない。

動画版の停止は次と同等のコマンドを使用する。

```text
tailscale serve --yes --https=8443 off
```

停止対象を8443に限定し、音楽版の443を巻き込まない。

## Windowsランチャー

「外部接続（Tailscale）」欄に `外部URLを開く` ボタンを追加する。

- 動画版8443のServeが有効な場合だけボタンを有効化
- 表示するURLも `:8443/` の動画版URLだけを対象にする
- HTTPS 443に音楽版だけが存在する状態を、動画版の「外部接続は有効」と誤判定しない
- ボタン押下で既定ブラウザに動画版外部URLを開く

## URL判定

`tailscale serve status` の出力から、通常の最初のHTTPS URLではなく `:8443` のURLを動画版として抽出する。

例:

```text
https://sample.ts.net
|-- / proxy http://127.0.0.1:8765

https://sample.ts.net:8443
|-- / proxy http://127.0.0.1:8876
```

この場合、動画版が表示・起動するURLは次だけである。

```text
https://sample.ts.net:8443/
```

## 変更しないもの

- 動画ローカルサーバーのポート `8876`
- 音楽版のローカルポート `8765`
- 音楽版のHTTPS 443 URL
- Tailscale Funnelは使用しない
- ルーターのポート開放は行わない
- 動画・字幕ファイルは変更しない

## 回帰テスト

- 443の音楽版だけが存在するとき、動画版外部接続を有効と判定しない
- 443と8443が共存するとき、動画版URLとして8443を取得する
- 動画版の有効化コマンドが `--https=8443` を使用する
- 動画版の停止コマンドが8443だけを停止する
- Windowsランチャーに `外部URLを開く` ボタンとハンドラーが存在する

- 440作品 / 4,869動画fixture
