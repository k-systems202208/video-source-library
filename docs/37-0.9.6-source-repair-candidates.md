# 0.9.6 元データ異常の修復候補探索

## 背景

0.9.5の実機全件監査では、登録4,869件のうち実動画4,845件は `applicationNoRoute = 0` でアプリ側の再生互換性に未解決項目がないことを確認した。一方、24件は動画拡張子を持ちながら実体がASS/SRT字幕データで、元データ修復待ちとして分離されている。

## 変更内容

- `SUBTITLE_CONTENT_REGISTERED_AS_VIDEO` / `MISSING_FILE` / `NO_VIDEO_STREAM` などの元データ異常について、同一フォルダー内を読み取り専用で探索する。
- 動画拡張子だけでは候補にせず、ffprobeで映像ストリームを持つことを確認する。
- エピソード番号一致を優先し、ファイル名類似度を加味して最大3件を提示する。
- 候補は絶対パスを出さず、動画ルートからの相対パスだけをJSON / 元データ異常CSVへ出力する。
- `sourceDataErrorsWithCandidates` / `sourceDataErrorsWithoutCandidates` を監査summaryへ追加する。
- ランチャー完了画面で「修復候補あり / 候補なし」を明示する。

## 安全性

本機能は候補提示だけを行う。元動画・字幕・SQLite・PlaybackCacheを移動、改名、削除、差し替えしない。候補の採用は必ず利用者が元ファイルを確認したうえで手動で行う。

## v1.0前の扱い

アプリ側の再生互換性は0.9.5実機監査で合格済み。0.9.6は残る24件の元ライブラリ修復を安全に進めるための補助機能であり、元データ異常をアプリ側の再生失敗として扱わない方針は維持する。
