# 0.7.8 MKV複数音声の日本語優先再生

## 背景

MKVに英語音声と日本語音声の両方が格納されている場合、ブラウザ再生では英語音声が先に選択される動画がある。

確認例:

```text
[Anime Time] Attack On Titan - 01.mkv
English 5.1 FLAC
Japanese 2.0 FLAC
```

デスクトッププレーヤーでは利用者が音声トラックを切り替えられるが、ブラウザの標準 `video` 要素から複数音声トラックを操作するAPIはブラウザ差が大きい。そのため、JavaScriptだけに依存せず、配信側でも日本語を優先する。

## 方針

英語と日本語を含む複数音声MKV/WebMでは、日本語音声を既定再生の候補として優先する。

次の原則は維持する。

- 元動画を変更しない
- 元動画を移動・改名しない
- 再エンコードしない
- 一時的な変換動画を作成しない
- ファイルサイズを変えない
- HTTP Rangeとシーク位置を変えない

## Matroska配信時の処理

`windows-installer/src/matroska_audio.py` がMatroskaの `Tracks` 要素だけを解析する。

複数のAudio `TrackEntry` があり、日本語トラックを識別できた場合だけ次を行う。

1. 日本語Audio `TrackEntry` をAudioトラック群の先頭へ配置する
2. `FlagDefault` が明示されている場合、日本語を `1`、その他の音声を `0` にする
3. `Tracks` / `TrackEntry` にCRC-32がある場合は再計算する
4. 元と完全に同じバイト長の置換データをメモリ上だけで作成する
5. `/video/<id>` の配信チャンクがその領域と重なる場合だけ置換して送信する

動画ファイルそのものには書き込まない。

## 日本語判定

次を日本語として扱う。

- Language / LanguageIETF: `ja`, `jpn`, `jp`, `japanese`
- `ja-*`, `jpn-*`
- Track Nameに `Japanese` または `日本語` を含む

## 安全側フォールバック

次の場合はコンテナへ一切補正せず、従来どおり元ファイルをそのままRange配信する。

- 日本語音声がない
- 音声トラックが1本だけ
- Matroska構造を安全に解析できない
- Tracksが上限サイズを超える
- Segment全体にCRC-32があり、局所補正だけでは整合性を維持できない
- MKV/WebM以外

不明な形式を推測で書き換えない。

## ブラウザ側フォールバック

`HTMLMediaElement.audioTracks` が利用できるブラウザでは、`loadedmetadata` / `addtrack` 時にも日本語トラックを選択する。

これは補助経路であり、Chrome等でAPIが利用できない環境ではMatroska配信側の日本語優先を使用する。

## 対象外

0.7.8では次を行わない。

- MP4等のコンテナ内部音声トラック順の変更
- FFmpegによるremux / transcoding
- 音声トラック選択UIの追加
- 音声情報のDBスキーマ追加
- 外部字幕再生機能の変更

## 回帰テスト

- 英語default + 日本語non-default → 日本語を先頭/defaultへ
- FlagDefault省略時も日本語を先頭へ
- Languageタグが不十分でもTrack NameのJapaneseから判定
- 単一音声 / 日本語なし / 非Matroskaは無変更
- Tracks CRC-32再計算
- Segment CRC-32ありは安全側フォールバック
- 部分Rangeでも元オフセット・Content-Lengthを維持
- `/video/<id>` の実HTTP配信で補正後バイト列を確認
- ブラウザ側 `audioTracks` 日本語優先処理の存在確認

CIでは従来どおりPython 3.11 / 3.13、440作品 / 4,869動画fixture、Windowsインストーラー生成を維持する。
