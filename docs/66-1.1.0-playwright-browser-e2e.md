# 1.1.0 Playwright ブラウザE2E

## 目的

PythonのユニットテストやHTML文字列テストだけでは検出できない、実ブラウザ上のUI回帰をCIで検出する。

特に、JavaScriptが読み込まれていてもイベントが発火しない、館内メニューから遷移できない、作品カードや作品詳細が描画されない、といった問題をWindows Installer生成前に止める。

## 実行環境

- Chromium
- Playwright 1.55.0
- Node.js 22
- Python 3.13
- Windows GitHub Actions runner
- 合成ライブラリ: 12作品 / 24動画

実データは使用せず、既存のCI合成メタデータ生成処理を使ってE2E専用サーバーを起動する。

## Viewport

同一シナリオを次の3 projectで実行する。

- PC: 1440 x 900
- Tablet: 1024 x 768
- Smartphone: 390 x 844

## ブラウザE2E項目

### 初期表示

- 「関町北映画館」ヘッダーが表示される。
- 作品目録が表示される。
- 12作品のカードが描画される。
- 初回表示時のスクロール位置がページ先頭である。

### 左メニュー5項目

実際にクリックし、以下すべてのルートが動作することを確認する。

1. 上映中
2. 次回上映
3. 作品目録
4. 監督／演出
5. 主な出演者／声優

人物メニューでは、合成データの「テスト監督」「テスト出演者」が実際に一覧へ描画されることも確認する。

### 作品カード・作品詳細

- 最初の作品カード「テスト作品001」が表示される。
- カードをクリックすると作品詳細ルートへ遷移する。
- 詳細画面に作品名が表示される。
- 「← 作品目録」ボタンが表示される。

### レスポンシブ

- PCでは左ナビが常時表示され、ハンバーガーメニューは非表示。
- Tablet / Smartphoneではハンバーガーメニューが表示され、開くと5項目が表示される。
- ヘッダー内の館名パネルが画面中央に配置される。
- 横スクロールが発生しない。

### JavaScript runtime

各テストでブラウザの pageerror を監視し、JavaScript例外が1件でも発生した場合はE2E失敗とする。

## CIゲート

browser-e2e job が成功しない限り、installer job は開始しない。

失敗時には以下を Playwright-E2E-Diagnostics artifact として保存する。

- HTML report
- screenshot
- trace
- video

これにより、CI上で再現したUI不具合を実画面・操作履歴付きで確認できる。
