# 0.6.8 中断スキャン回収

## 背景

スキャン中にWindows版を終了すると、`scan_runs.status='RUNNING'` が永続DBへ残る場合があります。
スキャンワーカーはプロセス内スレッドのため、次回起動時にその処理が継続することはありません。

0.6.7以前は永続DBのRUNNING行をそのまま「現在も処理中」と判定していたため、再起動後に進捗モーダルが次の状態で固定されることがありました。

- 処理中
- 対象数を確認中
- MATCHED / MISSING / NEW_FILE = 0
- 経過時間 = `—`
- 現在処理中 = `—`

## 0.6.8の修正

Windowsランチャーはサーバー開始前に、残っている `RUNNING` 行を `INTERRUPTED` へ更新します。
`completed_at` も設定し、履歴として中断されたことを保持します。

動画ファイル、作品メタデータ、字幕、視聴状態、お気に入りは変更しません。

これにより再起動後は古いスキャンを実行中と誤認せず、新しい再スキャンを開始できます。

## テスト

`tests/test_scan_recovery.py` で以下を確認します。

- RUNNING行がINTERRUPTEDへ回収される
- `latest_scan_status().running` がfalseになる
- completed_atが設定される
- SUCCESS済みスキャンは変更されない
