# 1.1.0 TMDb作品画像キャッシュ識別修正

## 現象

作品情報は正しいTMDb作品を参照しているにもかかわらず、ポスター・背景だけ以前の別作品画像が表示される場合がある。

実機では work_id=153「電車男」で、ドラマ版の作品情報に対して映画版の画像が残っていた。

## 原因

従来の作品画像キャッシュ名は次の形式だった。

```
poster/{work_id}.jpg
backdrop/{work_id}.jpg
```

そのため同じwork_idのTMDbリンクが別作品へ修正されても、旧画像と新画像の拡張子が同じ場合は同一ファイル名になる。

同期処理ではリンク変更を検出して強制更新する処理があるが、過去に残った旧キャッシュや、同期を再実行せず通常表示だけを行う環境では既存ファイルがそのまま返される可能性があった。

## 修正

作品画像のキャッシュ名にTMDb `remote_path` のSHA-256先頭12桁を含める。

```
poster/{work_id}-{remote_path_hash}.jpg
backdrop/{work_id}-{remote_path_hash}.jpg
```

これにより、

- work_idが同じ
- 拡張子も同じ
- TMDb画像パスだけが変わった

場合でも必ず別キャッシュになる。

画面/APIで使用するURLは変更しない。

```
/tmdb-image/poster/{work_id}
/tmdb-image/backdrop/{work_id}
```

画像エンドポイントはDBの現在の `poster_path` / `backdrop_path` から新キャッシュ名を計算する。

## 旧キャッシュ

従来の `{work_id}.jpg` は自動的に参照されなくなる。

破壊的な削除は行わない。現在のremote_pathに対応する新キャッシュが無い場合は、既存のon-demand repairによって現在のTMDb画像を取得する。

これにより既存ユーザー環境でも、アプリ更新後の画像アクセス時に自然に正しいキャッシュへ移行する。

## 人物画像

人物画像は `tmdb_person_id` をキャッシュキーとしており今回の同名作品問題とは独立しているため変更しない。

## テスト

- 同じwork_idでもremote_pathが変わればキャッシュパスが変わる。
- 旧 `{work_id}.jpg` が存在しても現在画像として利用しない。
- posterのon-demand repairが現在のremote_pathを `w500` で取得する。
- backdropのon-demand repairが現在のremote_pathを `w1280` で取得する。
