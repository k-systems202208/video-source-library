# 1.1.0 出演者顔写真の理由別監査レポート

## 目的

第2照合後も `PROFILE NOT AVAILABLE` の人物について、HTMLだけでは判断できない原因をアプリのDB・TMDb作品照合・credits・人物検索キャッシュから理由別に分類する。

## 出力

`diagnostics` フォルダーへ次の2ファイルを生成する。

- `tmdb-people-audit-YYYYMMDD-HHMMSS.json`
- `tmdb-people-audit-YYYYMMDD-HHMMSS.csv`

JSONは解析用の詳細情報、CSVは目視確認・共有用。

## 理由コード

- `PROFILE_READY`: TMDb人物照合済みで `profile_path` あり。
- `PERSON_NO_PROFILE`: TMDb人物照合済みだがTMDb側に `profile_path` がない。
- `NO_MATCHED_WORK`: その人物が登録されている作品にTMDb `MATCHED` が1件もない。
- `CREDIT_NAME_MISMATCH`: TMDb人物検索の候補が対象作品credits内に1人だけ存在するが、現在の人物リンクには反映されていない。表記差・旧名などの追加照合候補。
- `PERSON_SEARCH_NOT_IN_CREDITS`: 人物検索には候補があるが、その作品のcreditsには存在しない。誤マッチ防止のため自動確定しない。
- `CREDIT_PERSON_NOT_FOUND`: MATCHED作品はあるが、exact match・人物検索ともcredits内に候補を特定できない。
- `AMBIGUOUS`: 複数のTMDb person IDが候補になり、安全に自動確定できない。

## CSV項目

- `name` / `workCount` / `reason`
- `tmdbPersonIds` / `profilePaths`
- `matchedWorkCount` / `matchedWorks`
- `searchQueries`
- `directCreditIds`
- `constrainedSearchIds`
- `searchResultIds`
- `creditNameSample`

`matchedWorks` にはローカル作品名と `[movie|tv:TMDb ID]` を記録する。これにより、人物側の問題か作品側の問題かを追跡できる。

## 自動実行

人物写真同期とは別に `tmdb:people-audit-version = 1` を管理する。

- 人物同期が必要なら、人物同期完了後に監査も生成。
- 人物同期version 2が既に完了している既存環境では、アップデート後に監査だけをバックグラウンド実行。
- 手動の「TMDb同期」でも作品監査に加えて人物監査を生成。
- 監査成功後はversion 1完了マーカーを保存し、通常起動で毎回繰り返さない。

## ランチャーログ

監査完了時に各理由の件数と、人物監査JSON/CSVの保存先を表示する。

## 安全性

この変更は診断のみで、人物の自動紐付け条件は変更しない。既存の人物DB・作品DB・顔写真キャッシュを書き換えず、残件の原因分析に使用する。

表示バージョンは1.1.0のまま。
