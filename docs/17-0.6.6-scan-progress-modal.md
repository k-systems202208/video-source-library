# 0.6.6 再スキャン進捗モーダル

## 背景

実機で4,869動画と字幕を再スキャンすると処理時間が長く、従来UIはヘッダーに「読み込み中…」と表示するだけだった。処理が継続しているのか停止しているのか、どこまで進んだのか判断できなかった。

## 変更内容

### 非同期スキャン

`POST /api/scan` はスキャン完了までHTTP接続を保持せず、バックグラウンドスキャンを開始してHTTP 202を返す。

`GET /api/scan/status` は従来の永続化済みscan_runに加え、実行中だけメモリ上で管理する詳細進捗を `progress` として返す。

### progress

主なフィールド:

- `phase`: PREPARING / SCANNING / PROBING / SUBTITLES / FINALIZING / SUCCESS / FAILED
- `message`: 現在の処理説明
- `current`, `total`, `percent`
- `filesFound`, `filesMatched`, `filesMissing`, `filesNew`, `filesProbed`
- `subtitlesFound`, `subtitlesProcessed`, `subtitlesMatched`, `subtitlesUnmatched`
- `probeErrors`, `errors`
- `currentItem`: 動画ルートからの相対パスのみ。絶対パスは返さない
- `elapsedMs`, `etaMs`

詳細進捗はSQLiteへファイル単位で書き込まず、`ScanProgressStore` でプロセス内に保持する。耐久性が必要な最終結果だけを従来どおり `scan_runs` に保存する。

## UI

「再スキャン」を押すとモーダルを表示し、約1秒ごとに `GET /api/scan/status` をpollする。

表示内容:

- 現在フェーズ
- 進捗バーと処理件数
- MATCHED / MISSING / NEW_FILE
- 字幕検出 / 未紐付
- ffprobe解析件数
- 現在処理中の相対パス
- 経過時間 / 推定残り時間

モーダルを閉じてもスキャンは停止しない。スキャン中はヘッダーのボタンが「進捗を表示」に変わり、再度モーダルを開ける。

完了時は結果をそのままモーダルへ表示し、作品一覧・件数表示を自動更新する。失敗時はエラー内容をモーダルへ表示する。

## テスト

- scanner progress callbackがSCANNING / SUBTITLES / SUCCESSを通知すること
- `currentItem` に動画ルートの絶対パスが含まれないこと
- `POST /api/scan` が202を返すこと
- statusをpollしてSUCCESSになること
- `ScanProgressStore` の進捗率、完了、失敗状態
- Web UIに進捗モーダルとstatus pollingが含まれること
- 既存Phase 1〜6、440作品 / 4,869動画fixtureを壊さないこと
