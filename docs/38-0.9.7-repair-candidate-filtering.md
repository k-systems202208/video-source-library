# 0.9.7 修復候補から別エピソードを除外

## 背景

0.9.6実機監査では元データ異常24件のうち9件に修復候補が表示された。しかし `playback-audit-source-errors-20260915-164401.csv` を確認すると、9件の候補はすべて `EPISODE_MISMATCH` であり、対象話とは異なる同作品の別エピソードだった。

## 変更内容

- 対象ファイルと候補ファイルの双方からエピソード番号を抽出でき、番号が一致しない場合は修復候補から除外する。
- `sourceDataErrorsWithCandidates` / `sourceDataErrorsWithoutCandidates` は、このフィルター後の有効候補だけを基準に集計する。
- JSON / 元データ異常CSVにも別エピソードを修復候補として出力しない。
- エピソード番号が一致する別名動画は従来どおり候補として残す。

## 実ライブラリの期待値

0.9.6の実機CSVを基準にすると、24件について同一エピソードの別名動画は見つかっていない。

- 元データ異常: 24件
- 有効な修復候補あり: 0件
- 有効な修復候補なし: 24件

この24件はアプリの再生互換性不具合ではなく、元ライブラリ側で動画実体の再入手・復旧が必要な既知項目として扱う。

## 安全性

候補探索は引き続き読み取り専用である。元動画・字幕・SQLite・PlaybackCacheを変更しない。
