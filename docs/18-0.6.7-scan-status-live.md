# 0.6.7 再スキャン進捗取得のSQLite分離

## 背景

0.6.6実機で再スキャン進捗モーダルは表示されたが、`対象数を確認中` のまま更新されない事象が発生した。

## 原因

0.6.6の `GET /api/scan/status` は、ライブ進捗を返す前に通常のSQLite接続を開き `latest_scan_status()` を読み込んでいた。

スキャンワーカーは同時にSQLiteへ大量更新を行うため、実機ではstatus polling側が接続時のPRAGMAやDBロック待ちに入り、メモリ上では進捗が更新されていてもブラウザへ返せない可能性があった。

## 修正

- スキャン実行中の `/api/scan/status` はSQLiteを一切開かない。
- `ScanProgressStore` のスレッドセーフなメモリ状態だけを即時返す。
- スキャン終了後は従来どおりSQLiteの永続結果を参照する。
- PREPARINGが長引く場合は、ネットワークドライブまたはDB応答待ちであることを表示する。
- Windows版を0.6.7へ更新した。

## 回帰テスト

`tests/test_scan_status_live.py` では、スキャン中にサーバーのSQLite接続関数を意図的に利用不能にした状態でも `/api/scan/status` がHTTP 200で即時応答し、ライブ進捗を返すことを確認する。

これにより進捗監視は長時間のDB更新処理から独立する。
