# 1.1.0 TMDb作品照合・ポスター／背景画像

## 目的

TMDb連携基盤（schema 5 / Bearer認証 / APIレスポンスキャッシュ）を使い、登録作品を安全側でTMDbへ紐付け、確定できた作品だけ poster / backdrop をローカルへ保存してWeb UIへ表示する。

## 照合方針

- ローカルの正式作品名・原題、年、カテゴリを使用する。
- `映画` を含むカテゴリは movie、`ドラマ` を含むカテゴリは tv を検索する。
- アニメなど種別を一意に決めにくいカテゴリは movie / tv の両方を検索する。
- Unicode NFKC + 大文字小文字・記号差を吸収したタイトル類似度、公開年／初回放送年、poster有無からconfidenceを算出する。
- 高いタイトル一致度、年一致、候補間の十分なmarginを満たす場合だけ `MATCHED` にする。
- 低信頼・複数候補は `REVIEW` として残し、自動確定しない。
- 十分な候補がないものは `UNMATCHED` とする。
- 既に `MATCHED` の作品は再同期時に勝手に別作品へ付け替えない。

## APIキャッシュ

検索レスポンスは既存 `tmdb_api_cache` へ30日キャッシュする。cache keyは検索条件をSHA-256化し、API tokenを含めない。

## 画像キャッシュ

`MATCHED` だけを対象にTMDb CDNから取得する。

- poster: `%LOCALAPPDATA%\VideoLibrary\TMDbImages\poster\<work_id>.<ext>`
- backdrop: `%LOCALAPPDATA%\VideoLibrary\TMDbImages\backdrop\<work_id>.<ext>`
- posterは `w500`、backdropは `w1280`
- JPEG / PNG / WebPのみ許可
- 1画像20MiBを上限とする
- 一時ファイルからatomic replaceする
- 元動画・字幕・PlaybackCacheには触れない

ブラウザへはTMDb CDN URLやローカルファイルパスを返さず、`/tmdb-image/poster/<work_id>` と `/tmdb-image/backdrop/<work_id>` の同一origin URLだけを返す。PWAのCache Storageには入れず、ディスクキャッシュを正とする。

## 実行方法

ランチャーの `TMDb設定` でAPI Read Access Tokenを保存し、ライブラリ停止中に `TMDb同期` を実行する。処理はバックグラウンドスレッドで実行し、既存の進捗エリアに以下を表示する。

- MATCHED
- REVIEW
- UNMATCHED
- 現在処理中の作品

## 監査レポート

`%LOCALAPPDATA%\VideoLibrary\diagnostics` に次を出力する。

- `tmdb-match-audit-YYYYMMDD-HHMMSS.json`
- `tmdb-match-audit-YYYYMMDD-HHMMSS.csv`（UTF-8 BOM）

440作品の実機確認では、MATCHED件数だけでなくREVIEWの誤マッチ候補を作品単位で確認する。REVIEWを自動で画像表示へ昇格させない。

## Web UI

- 一覧カードはposterを縦長表示する。
- posterがない場合はタイトル入りフォールバックを表示する。
- 詳細画面はposterとbackdropを表示し、画像取得失敗時でも既存情報を表示する。
- TMDb overviewがある場合は詳細に表示する。
- TMDb attributionを画面内へ表示する。
