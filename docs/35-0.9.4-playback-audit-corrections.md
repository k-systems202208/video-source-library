# 0.9.4 全件再生監査の判定修正

## 背景

0.9.3で実ライブラリ4,869件を監査した結果、監査自体は完走したものの、`DIRECT 0 / TRANSCODE 4,844 / NO_ROUTE 25` となった。

調査の結果、次の3点を切り分けた。

1. DBに保存された拡張子が `mp4` / `webm` のように先頭ドットなしの場合、監査側の直接再生判定が常に失敗していた。
2. 監査用FFmpegサンプル変換はDIRECT動画までH.264 + AACへ再エンコードしており、AACの特殊な2chレイアウトで監査だけが失敗するケースがあった。
3. 24件はffprobeがコンテナを `ass` / `srt` と認識し、動画ストリームを持たないため、通常の動画破損とは別に扱う必要があった。

## 変更内容

### 拡張子正規化

`browser_direct_playback()` は `.mp4` と `mp4`、`.webm` と `webm` のどちらも受け付ける。これによりDB保存形式に依存せずDIRECT判定できる。

### 監査サンプルの実行方法

- `DIRECT`: ブラウザ互換形式への再エンコードは行わず、FFmpegで映像と優先音声を実デコードして確認する。
- `TRANSCODE`: H.264 + AACへのサンプル変換を行い、本番互換変換経路を確認する。
- サンプル出力はnullへ捨て、元動画・PlaybackCacheは変更しない。

### AAC音声の正規化

互換変換ではAAC出力を2chステレオへ正規化する。監査と本番の双方で同じ音声方針を使う。

変換プロファイルの世代を更新したため、0.9.3以前の変換キャッシュは再利用せず、新しい設定で必要時に再生成する。古いキャッシュは通常の容量管理対象として残り、上限超過時または手動削除で整理される。

### 動画登録だが実体が字幕のケース

ffprobeで動画ストリームがなく、コンテナ形式がASS / SSA / SRT / SubRip / WebVTTの場合は、`NO_VIDEO_STREAM` ではなく次の理由で記録する。

`SUBTITLE_CONTENT_REGISTERED_AS_VIDEO`

これは元ファイルを自動修正・削除するための判定ではない。メタデータ登録と実ファイルの対応を人が確認するための診断分類である。

## 0.9.3実監査からの期待値

再監査では、0.9.3で誤判定されたDIRECT件数が正しく分類され、AAC監査エラー1件が解消することを期待する。

24件のASS/SRT実体については `SUBTITLE_CONTENT_REGISTERED_AS_VIDEO` として残る想定であり、元データを確認するまでは自動変更しない。
