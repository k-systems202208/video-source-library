# 0.6.3 ローカルオーナー認証 hotfix

## 背景

0.6.2ではWindowsランチャーからlocalhostへのowner token登録HTTP POSTを廃止し、HMAC署名付きbootstrap tokenを直接exchange URLへ渡した。

実機ではHTTPリクエスト自体はVideoLibraryへ到達したが、`/api/local-auth/exchange?token=...` で401となった。CIでは同じフローが成功するため、ブラウザやローカルセキュリティ製品によるURL先読み・検査が、一度だけ有効なtokenを実際の画面表示より先に消費する可能性を考慮する必要がある。

## 0.6.3の変更

ランチャーが開くURLを次の形式へ変更した。

```text
http://127.0.0.1:<port>/offline.html?owner-bootstrap=1#token=<signed-token>
```

URL fragment（`#`以降）はHTTPリクエストには送信されない。そのため、最初のGETをURLスキャナ・先読み処理・プロキシ等が観測してもowner tokenはサーバーへ届かず、消費されない。

`offline.html` は `owner-bootstrap=1` の場合のみbootstrap画面として動作する。

1. `location.hash` からtokenを取得する。
2. 直ちに `history.replaceState()` でアドレスバー／履歴からtokenを除去する。
3. ブラウザJavaScriptからsame-originで既存 `/api/local-auth/exchange?token=...` を呼ぶ。
4. 成功時、サーバーが `HttpOnly; SameSite=Strict` owner session cookieを設定する。
5. `/` へ遷移する。
6. 失敗時はHTTP statusとVideoLibraryの安全なerror codeを画面表示する。

通常のoffline表示は維持する。

## セキュリティ

- owner tokenは初回HTTP requestに含めない。
- tokenは短寿命・HMAC署名付き・一回限りのまま維持する。
- tokenはJavaScriptが読み取った直後にブラウザ履歴から除去する。
- owner sessionは従来どおりHttpOnly / SameSite=Strict cookie。
- localhost以外へランチャーowner URLを生成しない。
- 既存のTailscale identity、Origin検査、owner権限制御は変更しない。

## 回帰テスト

`tests/test_owner_bootstrap.py` で以下を確認する。

- ランチャーURLのqueryにtokenが存在しない。
- tokenはfragmentにのみ存在する。
- 初回HTTP request pathにtokenが含まれない。
- bootstrap HTMLがfragment交換ロジックを含む。
- signed token exchangeでowner cookieが発行される。
- 同じtokenの再利用は401になる。
- 既存Phase 1〜6テストと440作品／4,869動画fixtureを維持する。
