# 1.1.0 監督／演出 顔写真（第2段階）

## 目的

人物名鑑の「監督／演出」にもTMDbのプロフィール画像を表示し、「主な出演者／声優」と同じ操作感で人物から作品を探せるようにする。

第1段階で確立した人物画像キャッシュ・アプリ内画像配信・人物カードUIは再利用し、人物同定の安全性を優先する。

## 照合方針

- ローカルの `director_or_direction` を正本として保持する。
- 作品自体がTMDbで `MATCHED` の場合だけ照合する。
- 映画は `/movie/{id}/credits`、TVは `/tv/{id}/aggregate_credits` の `crew` を利用する。
- `Director` / `Series Director` / `Episode Director` / `Co-Director` / `Chief Director` / `Supervising Director` など、Director系jobが明示されたクレジットだけを候補にする。`department=Directing` だけでは採用せず、Assistant Director等を監督として誤登録しない。
- 第2段階の初回は、ローカル人物名と `name` / `original_name` が正規化後に一意一致した場合だけ保存する。
- 同名候補が複数、Directingクレジットに存在しない、作品が未照合の場合は推測しない。
- 不一致は監査CSVで確認し、実ライブラリの結果を根拠に後続Issueで改善する。

## DB schema 7

`tmdb_work_people.role` に `DIRECTOR` を追加する。

既存schema 6からの更新ではテーブルを安全に再構築し、既存の `CAST` リンクをコピーして保持する。人物本体は `tmdb_people` を出演者と監督で共用するため、同一人物のプロフィール画像は重複保存しない。

## 画像

- 既存の `TMDbImages/person/{personId}.*` を共用する。
- サイズは `w185`。
- ブラウザには既存の `/tmdb-person-image/{personId}` から配信する。
- キャッシュ欠損時の自己修復も既存処理を利用する。

## UI

「監督／演出」名鑑も顔写真付き人物カードにする。

- 写真あり: TMDbプロフィール画像。
- 写真なし: `PROFILE NOT AVAILABLE`。
- カードクリック: 従来どおり「その人物が関わる登録作品」へ遷移。
- PC / Tablet / Smartphoneで同じレスポンシブ人物カードを利用する。

## 自動同期

人物同期versionを9へ更新する。

既存ユーザーでも次回起動時に人物同期が一度再実行され、CASTの既存処理に加えてDIRECTORを取得する。同期成功後は完了マーカーを更新する。

## 監査

同期後、従来の `tmdb-people-audit-*.csv/json` に加えて

- `tmdb-director-audit-YYYYMMDD-HHMMSS.csv`
- `tmdb-director-audit-YYYYMMDD-HHMMSS.json`

を diagnostics に出力する。

初回のreasonは次の通り。

- `PROFILE_READY`
- `PERSON_NO_PROFILE`
- `NO_MATCHED_WORK`
- `DIRECTOR_CREDIT_NOT_FOUND`
- `AMBIGUOUS`

この監査は第2段階の基準データであり、`DIRECTOR_CREDIT_NOT_FOUND` 等を推測で自動リンクするためには使用しない。

## テスト

- schema 6 → 7で既存CASTリンクを保持し、DIRECTORを追加できること。
- 映画のDirecting crewだけを照合すること。
- Production等の非Directing crewを誤照合しないこと。
- TV aggregate creditsのDirector jobを照合できること。
- 監督プロフィール画像をローカルキャッシュできること。
- `/api/people?role=director` が `profileUrl` を返すこと。
- Playwrightで監督写真、写真なしフォールバック、人物カード遷移をPC / Tablet / Smartphoneで確認すること。
- 既存CAST同期と人物監査を維持すること。
