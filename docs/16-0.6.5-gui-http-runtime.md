# 0.6.5 GUI版HTTPサーバー修正

## 現象

Windowsインストーラー版0.6.4を起動するとランチャーは `http://127.0.0.1:8876/` で実行中になるが、`/offline.html` と `/api/health` のどちらもChromeで `ERR_EMPTY_RESPONSE` になった。

## 原因

PyInstallerのspecは `console=False` でWindows GUIアプリを生成している。この実行形態では `sys.stdout` / `sys.stderr` が `None` になることがある。

Python標準の `BaseHTTPRequestHandler.send_response()` は内部で `log_request()` → `log_message()` を呼び、既定実装は `sys.stderr` へアクセスログを書き込む。stderrが存在しない場合、HTTPヘッダー送信前に例外になり、ブラウザ側では `ERR_EMPTY_RESPONSE` となる。

ソース実行やGitHub Actionsではstderrが存在するため、従来テストでは再現しなかった。

## 修正

`windows-installer/build/runtime_no_console.py` をPyInstaller runtime hookとして追加した。

- `sys.stderr is None` の場合 `%LOCALAPPDATA%/VideoLibrary/Logs/server.log` を割り当てる
- `sys.stdout is None` の場合も同じく書き込み可能なストリームを割り当てる
- ログディレクトリを作れない場合は `os.devnull` へフォールバックする
- runtime hookはアプリ本体より前に実行されるため、HTTPハンドラーを含む標準ライブラリのstderr依存も安全に処理できる

## 回帰テスト

`tests/test_gui_runtime.py` で `sys.stdout = None` / `sys.stderr = None` を再現してruntime hookを実行し、その状態で実際の `ThreadingHTTPServer` を起動する。

テストでは `/api/health` がHTTP 200を返すこと、および `Logs/server.log` にアクセスログが記録されることを確認する。

## 既存仕様

- 動画版localhostは `127.0.0.1:8876`
- 音楽版localhost `127.0.0.1:8765` とは引き続き分離する
- DB、`video_library.json`、設定、バックアップは `%LOCALAPPDATA%/VideoLibrary` に保持され、0.6.5への上書きインストールで失われない
